## 1. 开发环境

### 1.1 硬性要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10 / 11 x64 | PyInstaller 不能交叉编译，必须在 Windows 本机打包 |
| Python | **3.12（64 位）** | 统一由 miniconda 的 `game` 环境提供 |
| conda | miniconda（支持 `conda create`） | 负责解释器隔离，不使用 venv |
| pip | ≥ 23.0 | 保证安装 wheel，不触发源码编译 |
| 编辑器 | IntelliJ IDEA（Python 插件） | 解释器指向 conda `game`，支持 pytest 与类型提示 |
| 音频设备 | 任意（可无） | 无声卡时游戏静默运行，但开发阶段建议有声卡验证手感音效 |
| 显示器 | 建议 1920×1080 | 逻辑画布 1280×720，1080p 下 1:1 显示窗口最舒适 |

> 环境统一由 conda 管理。安装依赖前先 `where python` 确认第一条路径在 miniconda 的 `envs\game` 下，否则依赖会装进 base 或系统 Python。

### 1.2 创建 conda 环境

```powershell
conda create -n game python=3.12 -y
conda activate game
python --version          # 应输出 Python 3.12.x
```

若提示 `conda` 不是可执行命令，先打开「Anaconda Prompt (miniconda3)」；之后可 `conda init powershell` 让 PowerShell 直接可用。

### 1.3 IDEA 工程配置

1. `File → Project Structure → SDKs → Add SDK → Conda Environment`，选择 `game`。
2. `Run → Edit Configurations → + → Python`：Script path 指向 `main.py`，Working directory 设为工程根（`游戏/超级树里奥`）。
3. `Settings → Tools → Python Integrated Tools`：Default test runner 选 `pytest`，测试目录 `tests/`。
4. 右下角解释器路径应包含 `envs\game`，切换后 `import pygame` 不报错。

### 1.4 依赖安装

`requirements.txt`：

```text
pygame>=2.5.2,<2.7
pyinstaller>=6.3,<7
pytest>=7.4
pillow>=10.0        # 仅 tools/ 生成素材时需要，运行与打包不需要
numpy>=1.26         # 仅 tools/ 生成音频时需要，运行与打包不需要
```

```powershell
python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
python -m pip freeze > requirements-lock.txt
```

> `pillow` 与 `numpy` 只用于重新生成素材，不要写进 spec 的 `hiddenimports`；在 spec 的 `excludes` 中显式排除，避免误打包。

### 1.5 首次冒烟验证

```powershell
python -c "import sys; print(sys.version); print(sys.executable)"
python -c "import pygame; print(pygame.version.ver)"
python -c "import pygame; pygame.mixer.init(); print('mixer ok')"
python main.py
```

应弹出 1280×720 窗口进入主菜单；选 1-1 后角色站在地面上，按 → 能跑、按 ↑ 能跳、顶到第一个问号块出蘑菇。

## 2. 工程与命名规范

### 2.1 目录约定

- 源码一律放 `src/`，入口仅 `main.py` 一个；`src/entities/`、`src/ui/` 为子包。
- 二进制资源放 `assets/`，**只能**通过 `resource_path()` 访问；关卡放 `assets/levels/`，是**运行资源**，必须打包。
- 素材生成脚本放 `tools/`，不参与打包，也不写入 `assets/`。
- 测试放 `tests/`，文件名 `test_*.py`，**不得 import pygame**。
- 临时脚本、实验关卡放 `scratch/`（加入 `.gitignore`）。

### 2.2 命名规则

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 模块 | 小写下划线 | `tilemap.py`、`keymap.py` |
| 类 | 大驼峰 | `TileMap`、`LevelSession`、`PatrolShroom` |
| 函数/方法 | 小写下划线，动词开头 | `move_and_collide`、`on_stomp`、`snap_to` |
| 私有成员 | 单下划线前缀 | `_build_world`、`_player_hurt` |
| 常量 | 全大写 | `PHYSICS_DT`、`JUMP_VEL`、`TILE` |
| 枚举成员 | 全大写 | `SessionState.RUNNING`、`PowerState.FIRE` |
| 布尔量 | `is_` / `has_` / `can_` 前缀 | `on_ground`（状态量允许）、`can_stomp`、`has_hit_goal` |

### 2.3 代码风格

- PEP 8，单行 ≤ 100 字符，缩进 4 空格，UTF-8 无 BOM。
- 公开函数写类型注解；结构化数据用 `dataclass`，不用裸 dict 传状态。
- 关键算法（瓦片解算、单向平台、土狼时间、踩踏判定、相机死区、7 段式状态机）必须写中文注释说明**为什么**，而不是复述代码。
- 单个函数尽量 ≤ 80 行；`main()` 主循环按分支分段并加注释，允许更长。
- 禁止裸 `except:`；捕获需指明类型，并在注释中说明降级行为。
- 禁止在业务模块中 `print` 调试；未捕获异常写 `%APPDATA%\SuperTreeio\crash.log`。
- 格式化与静态检查建议：

```powershell
pip install black ruff
black --line-length 100 .
ruff check .
```

### 2.4 依赖方向的硬约束

以下为 Code Review 阻断项：

1. `physics.py`、`tilemap.py`、`camera.py`、`entities/*`、`game.py` 不得 import `pygame`。
2. `ui/` 只能读快照，不得修改 `TileMap` / `LevelSession` / 实体字段。
3. `game.py` 不得 import `audio` / `storage` / `ui`；音效与存档由 `main.py` 消费事件后处理。
4. `entities/*` 不得持有 `LevelSession` 引用，世界信息只能通过 `WorldView`（tilemap + 相机 + 玩家 x）获取。
5. 任何位置不得出现 `"assets/"` 形式的字面路径。
6. 任何位置不得写入 exe 所在目录（统一写 `%APPDATA%`）。

自查：

```powershell
Select-String -Path src\*.py,src\entities\*.py,src\ui\*.py -Pattern "import pygame|assets/|assets\\|\.\.\.assets"
```

```

```

一次提交只做一件事；关卡调整与代码修改分开提交，便于回滚。

## 4. 调试与开发辅助

### 4.1 调试开关

`config.py` 中：

```python
DEBUG = False        # 发布前必须为 False
```

`DEBUG=True` 时额外开放：

| 快捷键 | 作用 |
| --- | --- |
| `F1` | 绘制调试信息：帧率、实体数、玩家坐标/速度/状态、相机 x、当前物理步数 |
| `F2` | 重载当前关卡（改完 JSON 不用重启游戏） |
| `F3` | 切换无敌（不受伤、不掉坑），用于试关卡可行性 |
| `F4` | 绘制所有 AABB 边框与瓦片碰撞标记（单向平台用蓝框、尖刺用红框） |
| `Tab` | 传送玩家到相机中心（配合 `F2` 快速跳到关卡中段） |

发布版必须 `DEBUG=False`，此时以上按键全部不响应，也不得保留任何作弊入口。

### 4.2 关卡热改流程

1. 编辑器打开 `assets/levels/w1-1.json`，改 `tiles` 里的字符串或 `entities`。
2. 游戏内按 `F2` 重载（`DEBUG=True`）。重载会重新解析并校验，出错时在屏幕左上角显示 `LevelError` 文本而不是闪退。
3. 校验规则见 03 §2.2：行数 18、行长 = cols、图块码合法、`spawn` 周围为空。
4. 关卡改完必须跑一次「可通关性检查」（05 §2.5 的脚本），避免出现跳不过去的深坑。

> 强烈建议在编辑器里把 `tiles` 行按 40 字符分段加换行再手改，否则 200 字符一行极易错位。改完用 `python tools/format_level.py --check` 校验行长（脚本可选，见 08 §5）。

### 4.3 固定局面复现

单元测试需要在没有图形的情况下构造地形与实体：

```python
def make_session(tiles: list[str], spawn=(3, 14), entities=None):
    """用内存字典构造关卡，避免依赖真实 JSON 文件。"""
    data = {
        "id": "test", "name": "测试关", "theme": "grass",
        "cols": len(tiles[0]), "rows": len(tiles),
        "time": 300, "spawn": list(spawn),
        "tiles": tiles, "entities": entities or [],
    }
    tmap = TileMap.from_dict(data)
    session = LevelSession.from_dict(data, Profile())
    return session, tmap
```

用法（构造「中间一个 8 格宽的坑」，共 18 行）：

```python
rows = ["." * 20 for _ in range(13)]     # 顶部 13 行空
rows += ["#" * 6 + "." * 8 + "#" * 6]    # 地面只留两侧，中间是坑
rows += ["." * 20 for _ in range(4)]     # 坑底为空 → 掉出去即死亡
session, _ = make_session(rows, spawn=(2, 12))   # 脚底落在第 12 行底面，正好站在地面上
```

> `LevelSession.from_dict()` 是为测试预留的构造入口，`from_file()` 内部同样走它；生产代码不允许绕过文件加载。

### 4.4 无头测试

`pytest` 不需要显示设备，因为模型层不 import pygame。若测试意外初始化了 video/mixer：

```powershell
$env:SDL_VIDEODRIVER="dummy"
$env:SDL_AUDIODRIVER="dummy"
```

### 4.5 性能观察

- `DEBUG=True` 时 `F1` 叠加显示：`FPS`、`substeps`（本帧物理步数）、`entities`（存活实体数）、`player.vx/vy`。
- 若 `substeps` 长期等于 6，说明单帧耗时超过 50 ms，先查渲染（是否每帧 `smoothscale` 大图）和实体更新（是否遍历了全关卡实体）。
- 关卡宽度 200 格时同屏最多约 35 个图块列 × 18 行 ≈ 630 次 blit，正常情况远低于 60 FPS 的预算。

### 4.6 素材修改流程

1. 改 `tools/gen_tiles.py` / `gen_sprites.py` / `gen_backgrounds.py` / `gen_audio.py` / `gen_levels.py` 中的参数、配色、旋律或关卡布局。
2. 重新执行：

```powershell
python tools\gen_tiles.py
python tools\gen_sprites.py
python tools\gen_backgrounds.py
python tools\gen_audio.py
python tools\gen_levels.py
python tools\format_level.py
```

3. 目视／试听确认，再提交新的二进制素材；**不要**手工改 `assets/` 后让脚本与产物不一致。

| 4 | `game.py`（会话 + 踩踏 + 顶砖 + 死亡/重生） | 用一个 20 列小人造关卡跑通「走—跳—踩—顶—死—复活」 |

| 9 | 打包 | 06 文档验收清单全通过 |

## 6. 常见环境问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `pip install pygame` 报 `Microsoft Visual C++ 14.0 required` | Python 版本/架构没有对应 wheel | 确认 `python -V` 为 3.12 x64，在 `game` 环境内安装 |
| `pygame.error: No available video device` | 无图形会话（远程/服务） | 本地桌面运行；或 `SDL_VIDEODRIVER=dummy` 仅用于测试 |
| `pygame.error: WASAPI can't initialize audio client` | 无声卡、音频服务被禁用 | 正常现象，`Audio` 已降级；可在设置里把音效音量调 0 |
| 中文显示成方块 | 未加载中文字体 | 用 `assets/fonts/msyh.ttc`，经 `resource_path` 加载 |
| 窗口一闪而过 | 主循环异常且无控制台 | 终端里 `python main.py` 看堆栈 |
| 高 DPI 下文字发虚 | 未声明 DPI 感知 | `pygame.init()` 前调用 `SetProcessDpiAwareness(1)`（06 §6.5） |
| 角色穿墙 | 物理步数不足 / 速度过大 | 确认 `PHYSICS_DT = 1/120`、`MAX_SUBSTEPS ≥ 4`；检查是否用了可变 `dt` 做物理 |
| 站在单向平台上仍下落 | `prev_bottom` 判定缺失或容差过大 | 按 03 §3.3 用 `prev_bottom <= r*TILE + 0.5` |
| 贴墙时角色抖动 | 一次性斜向解算或未分轴 | 严格按「先水平后垂直」实现 |
| 按一次跳两次 | 每个物理子步都重新采样输入 | 每帧只 `sample()` 一次，子步共用 |
| 顶砖不破 | 未按体型判断 | `SMALL` 只弹，`BIG/FIRE` 才 `remove` |
| 敌人提前掉坑消失 | 未做激活/边缘检测 | 进入相机 200 px 才 `active`，巡逻类加 `ground_ahead` 掉头 |
| 改完关卡不生效 | 未按 F2 / 打包后读的是包内文件 | 开发期 F2 重载；发布版关卡随包，不能热改 |
| 音效延迟明显 | mixer buffer 过大 | `mixer.init(buffer=512)` |
| IDEA 报 `ModuleNotFoundError: pygame` | 解释器指向 base/系统 Python | 切换 SDK 到 conda `game` |
| PyInstaller 报找不到 pygame | 打包环境与运行环境不一致 | 在同一个 `game` 环境内安装并打包 |
