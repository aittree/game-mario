## 2. 图片素材

### 2.1 清单

| 文件 | 尺寸 | 格式 | 用途 | 绘制方式 |
| --- | --- | --- | --- | --- |
| `images/bg_menu.png` | 1280×720 | PNG RGB | 主菜单 / 选关 / 设置 / 排行榜 / 结算背景 | 整屏 1:1 blit |
| `images/logo.png` | 512×512 | PNG RGBA | 主菜单标题徽标 | 缩放到 300×300 居中 |
| `images/tiles_*.png` | 320×80 | PNG RGBA | 4 套主题地形瓦片 | 按 16 帧切图，每帧 40×40 |
| `images/bg_*_*.png` | 1400×720 | PNG RGB（近景为 RGBA） | 主题远景/近景视差层 | 按相机偏移平铺 blit |
| `images/player_small.png` | 288×192 | PNG RGBA | 小体型 15 帧动画 | 按帧索引切 48×48 |
| `images/player_big.png` | 288×288 | PNG RGBA | 大体型 16 帧动画（含蹲下） | 按帧索引切 48×72 |
| `images/enemies.png` | 192×240 | PNG RGBA | 四类敌人 9 帧 | 按 48×48 网格 |

| `icon.ico` | 多尺寸 | ICO | exe 文件图标 | 不参与运行 |

### 2.2 瓦片集（`tiles_*.png`）

固定 **8 列 × 2 行 = 16 帧**，每帧 40×40，**索引顺序不可变**，`Renderer` 按索引取图：

| 索引 | 图块 | 对应图块码 | 说明 |
| --- | --- | --- | --- |
| 0 | 土块 | `#` | 地面主体，顶部 4 px 草/石边缘，下部暗色 |
| 1 | 砖块 | `B` | 砖纹 + 浅色灰缝，可破坏 |
| 2 | 硬块 | `M` | 金属灰蓝，四角高光，不可破坏 |
| 3 | 问号块（帧 0） | `?` | 金色底 + 白色 `?`，轻微起伏 |
| 4 | 问号块（帧 1） | `?` | 与 3 交替播放，0.4 s 一轮 |
| 5 | 已用块 | `X` | 暗金无问号 |
| 6 | 水管管身 | `P` | 绿色竖纹 |
| 7 | 管口—左半 | `P` | 2 格宽水管的左半管口 |
| 8 | 管口—右半 | `P` | 2 格宽水管的右半管口 |
| 9 | 管口—单列 | `P` | 单格宽水管（关卡中尽量少用） |
| 10 | 单向平台 | `=` | 木板/石台，顶面实线、下方留空 |
| 11 | 尖刺 | `^` | 银白三角，底边贴格底 |
| 12 | 金币（帧 0） | `c` | 正面圆币 |
| 13 | 金币（帧 1） | `c` | 略窄 |
| 14 | 金币（帧 2） | `c` | 侧面细线 |
| 15 | 金币（帧 3） | `c` | 略窄（与帧 1 对称） |

**主题差异**：四套瓦片集只换配色与材质细节，**索引与形状完全一致**——这样切换主题不影响任何碰撞与关卡逻辑，也允许「草原关卡复用地下瓦片」做特殊段落。

绘制要求：

- 每帧四边留 1 px 透明安全边，避免相邻格出现细缝；
- 土块/砖块/硬块必须能无缝拼接（左边缘与右边缘像素连续）；
- 问号块与金币帧必须共用同一轮廓，切换时不能跳动；
- 尖刺的三角形底部对齐格底，高度不超过 28 px（保证玩家从上方经过时「看起来没有踩到」）。

### 2.3 玩家精灵表

两张表结构相同：**6 列 × 4 行**，帧尺寸分别 48×48 / 48×72。

`player_small.png`（288×192）：

| 行 | 帧 0 | 帧 1 | 帧 2 | 帧 3 | 帧 4 | 帧 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 站立 | 跑 1 | 跑 2 | 跑 3 | 跑 4 | 空 |
| 1 | 起跳 | 下落 | 打滑 | 受伤 1 | 受伤 2 | 空 |
| 2 | 变大 1 | 变大 2 | 死亡 1 | 死亡 2 | 空 | 空 |
| 3 | 预留 | 预留 | 预留 | 预留 | 预留 | 预留 |

`player_big.png`（288×288）同结构，第 3 行第 0 帧为「蹲下」，其余预留。

绘制要求：

- 角色**脚底对齐帧底边**、水平居中，碰撞盒（26×36 / 26×56）小于帧尺寸，视觉体积与碰撞体积分离；
- 朝右绘制，朝左由代码水平翻转；
- 红衣（`#E63B2E`）+ 蓝背带（`#2E5BFF`）+ 肤色脸，帽子与鞋为深色，保证在草原蓝天、地下暗背景上都可辨识；
- 火力状态使用**同一套帧**，由代码叠加暖色描边或整体调色（避免再画一张表）；
- 死亡帧只画上半身 + 惊讶表情，配合向上弹起的位移。

### 2.4 敌人精灵表（`enemies.png`）

4 列 × 5 行，帧 48×48：

| 行 | 内容 | 用到的帧 |
| --- | --- | --- |
| 0 | 巡逻菇 | 0、1（左右脚交替，0.18 s 一轮） |
| 1 | 甲壳虫行走 | 0、1（0.16 s 一轮） |
| 2 | 甲壳虫壳 | 0（静止壳，单帧） |
| 3 | 飞行蝠 | 0、1（翅膀上下，0.12 s 一轮） |
| 4 | 水管花 | 0、1（花头开合，0.20 s 一轮） |

绘制要求：

- 所有敌人**面朝左**绘制，朝右由代码翻转；
- 巡逻菇要有明显的「眼睛 + 眉毛」表情，压扁时靠代码压缩纵向缩放，无需单独帧；
- 甲壳虫壳与行走帧必须**同宽同底边**，缩壳时视觉不跳；
- 飞行蝠的翅膀不要超出 48×48 边界；
- 水管花的茎部下端要能接住水管口，露出高度由代码控制（精灵本身画满 46 px 高）。

### 2.5 道具精灵表（`items.png`）

4 列 × 3 行，帧 48×48：

| 行 | 内容 | 帧 |
| --- | --- | --- |
| 0 | 变大菇 | 0（单帧） |
| 1 | 火花 | 0、1（0.25 s 一轮） |
| 2 | 火球 | 0～3（0.05 s 一轮，4 帧旋转） |

火球在 48×48 帧内只画 24×24 的实体，其余透明；这样切图规则统一，不需要第二套网格。

### 2.6 背景

| 文件 | 尺寸 | 说明 |
| --- | --- | --- |
| `bg_menu.png` | 1280×720 | 主菜单；左下暗、右上亮，中央留出 Logo 与按钮区域，不含任何文字 |
| `bg_<theme>_far.png` | 1400×720 | 远景层，**可水平平铺**（左右边缘可无缝对接），视差系数 0.35 |
| `bg_<theme>_near.png` | 1400×720 RGBA | 近景层，透明底，视差系数 0.70；只画山丘/树/岩壁/旗杆剪影这类深色轮廓 |

四套主题的美术方向：

| 主题 | 远景 | 近景 | 主色 |
| --- | --- | --- | --- |
| 草原 | 蓝天渐变 + 白云 + 远山 | 绿丘、灌木剪影 | `#5C94FC` / `#5DBB46` |
| 地下 | 深紫黑空洞 + 砖墙剪影 | 钟乳石、矿灯剪影 | `#0B0A1F` / `#2A2440` |
| 空中 | 高空浅蓝 + 层云 | 云团、远处浮岛剪影 | `#7FC8FF` / `#E6F6FF` |
| 城堡 | 暗红棕天空 + 雷云 | 城垛、铁链、岩浆光剪影 | `#2A1426` / `#6B2A38` |

绘制要求：

- 远景层必须低对比、低饱和，避免抢地形与角色的视觉优先级；
- 近景层不透明度建议 55%～75%，只做「环境提示」，不遮挡地形；
- 背景中不得出现任何可被误认为金币/道具的高亮圆点。

### 2.7 图标

- `icon.png` 与 `icon.ico` 由同一张 Logo 生成，保证窗口图标与 exe 图标视觉一致。
- ico 必须含 16/24/32/48/64/128/256 七种尺寸；缺尺寸会导致任务栏、属性页显示模糊或空白。
- 256×256 的 ico 由 PNG 压缩存储（Windows Vista+ 支持），文件仅几十 KB。
- 图标主体是树里奥的帽子 + 一片叶子（呼应「树」），不要使用红底白字的「M」式构图，避免与第三方 IP 混淆。

## 3. 音频素材

### 3.1 技术规格

| 项 | 值 | 说明 |
| --- | --- | --- |
| 采样率 | 22050 Hz | 芯片音乐足够，体积减半 |
| 位深 | 16 bit | 兼容性最好 |
| 声道 | 单声道 | 不需要立体声定位 |
| 容器 | WAV（PCM） | 无需解码库，`pygame.mixer` 直接加载 |
| BGM | 24～30 s，可循环 | `pygame.mixer.music.play(-1)` |
| 初始音量 | 音乐 70 / 音效 80 | 见 `storage.Settings` 默认值 |

### 3.2 BGM（4 首主题曲）

| 文件 | 时长 | 主题 | 设计要点 |
| --- | --- | --- | --- |
| `bgm_grass.wav` | 28.0 s | 草原 | 大调、明亮方波主旋律 + 跳跃感低音，150 BPM |
| `bgm_cave.wav` | 26.0 s | 地下 | 小调、慢速、加混响感（用延迟叠加模拟），120 BPM |
| `bgm_sky.wav` | 30.0 s | 空中 | 高音区分解和弦、轻飘，170 BPM |
| `bgm_castle.wav` | 24.0 s | 城堡 | 半音下行、打击更重，140 BPM |

要求：首尾各 0.3 s 淡入淡出，循环接缝无「咔哒」爆音；同一主题内不出现人声采样。

### 3.3 音效清单与触发

| 文件 | 时长 | 触发时机 | 设计要点 |
| --- | --- | --- | --- |
| `sfx_jump.wav` | 0.12 s | 起跳成功 | 500→760 Hz 上行短滑音 |
| `sfx_coin.wav` | 0.10 s | 收集金币 | 两个高音（1.2 k / 1.8 k）快连，清脆 |
| `sfx_stomp.wav` | 0.08 s | 踩敌成功 / 踢壳 | 低频「噗」+ 短噪声 |
| `sfx_bump.wav` | 0.10 s | 顶砖/顶问号块 | 闷响，不刺耳，连顶不吵 |
| `sfx_brick.wav` | 0.16 s | 砖块破碎 | 噪声爆 + 下滑，明显区别于 `bump` |
| `sfx_powerup.wav` | 0.40 s | 变大 / 变火力 | 四级上行琶音 |
| `sfx_powerdown.wav` | 0.35 s | 受伤掉级 | 三级下行 + 轻微失真 |
| `sfx_fire.wav` | 0.08 s | 发射火球 | 短促「呼」声 |
| `sfx_death.wav` | 1.20 s | 死亡 / 游戏结束 | 上行到高点的滑稽音 + 下行收束 |
| `sfx_clear.wav` | 1.60 s | 通关 | 六音符上行 + 收尾和弦 |
| `sfx_checkpoint.wav` | 0.30 s | 触碰检查点 | 双音上行（旗子升起） |
| `sfx_oneup.wav` | 0.35 s | 满 100 金币加命 | 经典「叮-叮-叮」三连高音 |
| `sfx_menu.wav` | 0.05 s | 菜单悬停 / 点击 | 1.2 kHz 短促点击，音量仅 0.25 |
| `sfx_pause.wav` | 0.20 s | 暂停 / 继续 | 680→460 Hz（暂停）、460→680 Hz（继续）由代码选一个文件播放，统一用下行即可 |

**触发约束**（避免音画不同步或重复播放）：

- 音效由 `main.py` 消费 `GameEvent` 后播放，模型层不直接调 `Audio`。
- 同一帧内「锁定/顶砖/金币」可同时发生，各自独立通道并行播放，不排队。
- 火球撞地弹跳只播放一次 `sfx_fire`（发射时），弹跳不额外配音，避免连响。
- 暂停时 BGM `pause()`，音效自然结束；继续时 `unpause()` 从原位置续播。
- 切关时 `play_bgm(theme)`，同一主题不重播；跨主题从头播放。

### 3.4 音量与静音

- 音乐、音效音量独立存于存档，范围 0～100。
- 音量 0 时 BGM 静音（`set_volume(0)` + 暂停），音效 `play()` 直接返回。
- 无声卡环境下 `Audio.available=False`，所有调用安全跳过，不影响游戏逻辑与帧率。

## 4. 关卡素材

关卡是**内容资产**，与图片/音频同等级别管理，必须入 Git、必须入包。

| 文件 | id | 主题 | 列数 | 标准时间 | 设计定位 | 实体数量（参考） |
| --- | --- | --- | --- | --- | --- | --- |
| `w1-1.json` | 1-1 | grass | 200 | 300 | 教学：砖块、问号块、金币、巡逻菇、水管、检查点 | 23 |
| `w1-2.json` | 1-2 | cave | 170 | 300 | 尖刺、窄平台、密集甲壳虫 | 23 |
| `w1-3.json` | 1-3 | sky | 180 | 320 | 单向平台、移动平台、飞行蝠 | 22 |
| `w1-4.json` | 1-4 | castle | 190 | 340 | 水管花、长跳、密集尖刺 | 26 |

编写要求：

- 18 行、行长 = `cols`、图块码合法（见 03 §2）、`spawn` 周围干净；
- 顶部 2 行只放装饰性图块（`M` 做天花板也行，但不能形成可站立平台，否则会被 HUD 遮挡）；
- 每关必须有且仅有一个 `goal`，且距右边界 ≤ 6 格；
- 每个 `?` 块在 `items` 里有配置，未配置时默认产出金币；
- 关卡内建议单坑宽度 ≤ 5 格（实际冲刺跳跃可达更远，此处按 5 格控制容错与节奏；校验见 05 UT-L-07）；
- 关卡基线由 `tools/gen_levels.py` 生成；手工调整 JSON 后同样要重跑校验；
- 改关卡后必须跑 `python tools/format_level.py` 与 05 §2.7 的可通关性检查。

## 5. 生成脚本

素材**全部可复现**，不依赖手工操作：

| 脚本 | 输入 | 输出 | 依赖 |
| --- | --- | --- | --- |
| `tools/gen_tiles.py` | 参数（配色表 `TILE_COLORS`） | 4 套瓦片集（320×80） | Pillow ≥ 10 |
| `tools/gen_sprites.py` | 无（纯程序绘制） | `player_small.png`、`player_big.png`、`enemies.png`、`items.png`、`logo.png`、`bg_menu.png`、`icon.png`、`icon.ico` | Pillow ≥ 10 |
| `tools/gen_backgrounds.py` | 无（纯程序绘制） | 4 套远景 + 4 套近景（1400×720） | Pillow ≥ 10 |
| `tools/gen_audio.py` | 无（纯程序合成） | 4 首 BGM + 14 个音效 | numpy ≥ 1.26 |
| `tools/gen_levels.py` | 无（固定坐标 + 固定随机种子） | 4 个关卡 JSON | 标准库 |
| `tools/format_level.py` | `assets/levels/*.json` | 校验报告（行长、图块码、出生点、items、实体、goal、坑宽） | 标准库 |

运行：

```powershell
python -m pip install pillow numpy
python tools\gen_tiles.py
python tools\gen_sprites.py
python tools\gen_backgrounds.py
python tools\gen_audio.py
python tools\gen_levels.py
python tools\format_level.py
```

参数位置：

- 瓦片配色：`gen_tiles.py` 顶部 `TILE_COLORS`（与 `config` 中的 `*_RGB` 常量一一对应，改色需两处同步）。
- 瓦片 Grid：`CELL = 40`，一次生成 16 帧，按 §2.2 索引顺序绘制。
- 精灵：`gen_sprites.py` 顶部的调色常量（`RED`/`BLUE`/`SKIN` 等）与各 `draw_*_frame` 函数；角色帧按 §2.3 的行列布局绘制。
- 背景：`gen_backgrounds.py` 的 `W, H = 1400, 720` 与各主题绘制函数；远景/近景都按周期函数绘制，保证左右边缘可对接。
- 音乐：`gen_audio.py` 的 `bgms` 字典（每主题的时长、bpm、和声进行、旋律音型）。
- 关卡：`gen_levels.py` 的 `level_1()`～`level_4()`（固定坑位、水管、砖块与实体坐标）。

### 5.1 源图管理

本项目**全部素材均由脚本程序化生成**，不依赖 `_src/` 原图，也没有 AI 出图与手工抠图环节：

- `gen_sprites.py` 直接按 §2.3～§2.5 的行列布局用 Pillow 绘制角色、敌人、道具、Logo 与菜单背景，再用同一张 Logo 生成多尺寸 `icon.ico`。
- `gen_backgrounds.py` 用渐变、多边形与椭圆直接绘制远景/近景，并按 `W = 1400` 做左右边缘对接，保证可平铺。
- 若将来引入外部原图，统一放在 `_src/`（已被 `.gitignore` 忽略，不进 Git、不进打包），由脚本读取后处理；`_src` 中的图不得直接拷进 `assets/`。

### 5.2 修改素材的正确流程

1. 改脚本参数（或按需新增 `_src/` 原图）；
2. 重新执行对应脚本；
3. 目视检查：瓦片无缝、索引顺序、角色脚底对齐、敌人朝左；
4. 试听音频，重点听 BGM 循环接缝与金币/踩敌音是否刺耳；
5. 提交新的二进制产物，**不要**手工 P 图后让产物与脚本不一致。

## 6. 替换与换皮指南

| 想改什么 | 要动的文件 | 必须保持的约束 |
| --- | --- | --- |
| 瓦片配色 / 材质 | `gen_tiles.py` 的 `TILE_COLORS` + `config` 的 `*_RGB` | 两处同步；仍为 8×2 帧、40×40、索引不变 |
| 角色形象 | `gen_sprites.py` 的角色绘制函数 | 帧尺寸与行列布局不变；脚底对齐、朝右 |
| 敌人形象 | `gen_sprites.py` 的敌人绘制函数 | 48×48 网格、朝左、壳与行走同底边 |
| 背景风格 | `gen_backgrounds.py` 的主题绘制函数 | 输出 1400×720，远景可平铺，近景透明 |
| 标题 Logo | `gen_sprites.py` 的 Logo 绘制函数 | 输出 512×512 透明底，主体留 5% 安全边距 |
| 图标 | 随 Logo 一起生成 | ico 必须含 16～256 七种尺寸 |
| BGM | `gen_audio.py` 的 `bgms` 字典 | 时长 24～30 s，首尾淡入淡出，单声道 22050 Hz |
| 音效 | 对应 `sfx_*()` 函数 | 时长 0.05～1.6 s；归一化后再进游戏 |
| 关卡内容 | `tools/gen_levels.py`（或直接改 `assets/levels/*.json`） | 18 行、行长=cols、图块码合法、可通关 |
| 中文字体 | 替换 `assets/fonts/msyh.ttc` | 必须是 TrueType/OpenType 集合，且包含界面全部汉字 |

若替换字体，需回归 07 文档中的全部文案、HUD 数字与结算页，确认无缺字、无截断。
